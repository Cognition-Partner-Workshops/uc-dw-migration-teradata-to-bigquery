# Teradata → BigQuery (this repo)

## Layout

- Teradata source: `ddl/tables/`, `ddl/views/`, `dml/stored_procedures/`,
  `dml/macros/`, `dml/scripts/` (BTEQ).
- Seeds (pipe-delimited, `|`): `data/seed/*.csv`. Dimensions are hand-curated;
  the two fact seeds are regenerated by `python data/seed/_generate_fact_data.py`
  (deterministic — do not hand-edit).
- Parity contract: `verify/checks/*.sql` (signature queries) and
  `verify/expected/parity_checksums.csv` (golden). **Do not edit golden to pass.**
- Your deliverable: converted GoogleSQL in `bigquery/views/*.sql` (and, when
  extending, `bigquery/tables/`, `bigquery/procedures/`).

## Verify

```bash
pip install -r verify/requirements.txt
python verify/run_parity.py     # exit 0 = all parity metrics match golden
```

The harness loads the seeds into in-memory DuckDB (a local stand-in for
BigQuery), executes every `bigquery/views/*.sql`, runs the signature queries, and
diffs against golden. A tiny shim (`BQ_SHIM` in `verify/run_parity.py`) rewrites
backtick identifiers and `SAFE_DIVIDE`; otherwise keep converted SQL in the
**GoogleSQL/ANSI common subset** so it runs unmodified both here and on BigQuery.

## View contract the harness expects

Create these as `CREATE OR REPLACE VIEW <name> AS ...`:

| File | View name | Reads | Signature metrics |
|------|-----------|-------|-------------------|
| `01_vw_regulatory_large_transactions.sql` | `vw_regulatory_large_transactions` | `fact_transaction`, `dim_account`, `dim_customer`, `dim_branch` | `row_count`, `sum_base_amount`, `n_categories` |
| `02_vw_branch_monthly_performance.sql` | `vw_branch_monthly_performance` | `fact_monthly_account_snapshot`, `dim_branch` | `row_count`, `sum_cumulative_fees`, `sum_moving_avg_volume` |
| `03_vw_customer_360.sql` | `vw_customer_360` | `dim_customer`, `dim_account`, `fact_transaction` | `row_count`, `sum_total_accounts`, `sum_lifetime_txn_amount` |

Tables are referenced by **natural keys** (`ACCOUNT_ID`, `CUSTOMER_ID`,
`BRANCH_ID`) in the harness model — not the production surrogate keys.

## Teradata → BigQuery cheat sheet

`SEL`→`SELECT` · `QUALIFY`→`QUALIFY` · `ZEROIFNULL(x)`→`IFNULL(x,0)` ·
`NULLIFZERO(x)`→`NULLIF(x,0)` · `CSUM(x,k)`→`SUM(x) OVER (ORDER BY k ROWS BETWEEN
UNBOUNDED PRECEDING AND CURRENT ROW)` · `MAVG(x,n,k)`→`AVG(x) OVER (ORDER BY k
ROWS BETWEEN (n-1) PRECEDING AND CURRENT ROW)` · `HASHROW(...)`→
`FARM_FINGERPRINT(...)` · `ADD_MONTHS(d,n)`→`DATE_ADD(d, INTERVAL n MONTH)` ·
drop `LOCKING ROW FOR ACCESS`, `COMPRESS`, `COLLECT STATISTICS`.

## Known pitfall (the harness catches it)

`MAVG(volume, 3, month)` is a **3-row** moving average: `ROWS BETWEEN 2 PRECEDING
AND CURRENT ROW`. Writing `3 PRECEDING` averages 4 rows and the harness fails
with `MISMATCH 20_branch_performance.sum_moving_avg_volume`.
